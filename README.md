# NIFTY & BEYOND — unified research desk

One polished web front-end that ties three existing products into a single
"research and analysis" surface.

| Screen | What it shows | Source |
|---|---|---|
| **Today's close** (`#/`) | Latest edition headline + verdict tags, jump cards, recent editions | `data/reports.json` |
| **Daily report** (`#/report/<id>`) | The full post-market brief, embedded in-place, with a date switcher | `reports/**` (same repo in prod; `rajan1973.github.io/reports/**` from localhost) |
| **Rotation · RRG** (`#/rotation`) | The weekly Relative Rotation Graph app, embedded in-place | `rotation/` (copy of `rrg-nifty-indices`) |
| **Sector research** (`#/sectors` · `#/sectors/<id>`) | 21 Q1 FY27 sector earnings reviews, each opened in place | `data/sectors.json` + `sectors/*.html` |
| **Archive** (`#/archive`) | Every edition, card/list toggle, kind filter, text filter | `data/reports.json` |

Shared chrome: sidebar nav, ⌘K / Ctrl-K search across editions + sectors +
screens, the editorial paper design system, and an "educational use only"
footer.

## Design decisions

- **Unified reader, one URL.** Hash routing (`#/…`) — no server rewrites needed
  on GitHub Pages *or* Vercel.
- **One repo, two hosts.** Ships into `Rajan1973/Rajan1973.github.io` at the
  root. GitHub Pages keeps serving it as today; Vercel serves the *same* repo as
  the polished front door. Because `reports/`, `sectors/` and `rotation/` are in
  the deployment, every embed is **same-origin on both hosts** — the report /
  sector iframes auto-expand to full height, no proxy, no CORS. Full steps in
  `DEPLOY.md`.
- **Links only — no market data in the shell.** Every number lives inside the
  linked report or the RRG app. This front-end reads no database, so RLS on
  `nifty500data` is irrelevant to it. The embedded RRG app talks to its **own**
  read-only Supabase project (`RRG-Data`, publishable key, already public-safe).
- **Sectors are wired to source.** `scripts/sync-sectors.mjs` copies the
  `rajan-sector-analysis` HTML output into `sectors/` and regenerates
  `data/sectors.json`.
- **No build step, no framework.** Plain HTML + one CSS + one JS file, matching
  the rest of the ecosystem. `scripts/` uses Node with zero dependencies.

## Run locally

```bash
python -m http.server 4178      # or any static server; must be HTTP, not file://
# open http://localhost:4178
```

A launch config is provided (`.claude/launch.json`). On `localhost` the **report**
iframe is cross-origin (it pulls from `rajan1973.github.io`) so it keeps its own
scrollbar; the **sector** and **RRG** frames are local files and auto-expand.
In production everything is same-origin and everything auto-expands.

## Keeping it current

- **New daily edition** → prepend one object to `data/reports.json` `reports[]`
  (`id` `YYYY-MM-DD`, `k` one of `daily|expiry|fo|weekly`, `path` relative to the
  repo root). Home, report switcher, archive and search pick it up with no other
  change. `DEPLOY.md` has the exact shape and the `upload-post-mkt-report` wiring.
- **New / updated sector reviews** →
  `node scripts/sync-sectors.mjs "<path to rajan-sector-analysis project>"`,
  then commit `sectors/` + `data/sectors.json`. Ladder order and blurbs live in
  the `LADDER` array in that script.
- **New RRG build** → nothing to do; the embedded app reads live from its own
  project. To refresh the app shell, re-copy `rrg_app_updated.html` into
  `rotation/index.html`.
